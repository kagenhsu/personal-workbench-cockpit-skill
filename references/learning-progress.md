# 學習進度保存與交換規則

## 目的

讓工作台可以保存使用者或專案的學習進度，支援日後查詢、持續學習、復盤、導入與導出。進度資料要能被人閱讀，也能被另一個工作台或版本重新載入。

## 最小資料模型

使用 `LearningProgress`，至少包含：

- `schemaVersion`：交換格式版本，例如 `1`
- `id`：穩定識別碼
- `title`：課程、主題、技能或學習專案名稱
- `learner`：學習者或使用情境；不放不必要個資
- `status`：未開始／進行中／已完成／暫停／待確認
- `stage`：目前階段
- `percent`：0～100；未知時使用 `null`，不可自行猜測
- `startedAt`、`updatedAt`：可確認時才填寫
- `completedItems`：已完成項目與完成時間
- `nextAction`：下一個可執行行動與預計時間
- `evidence`：筆記、作品、測驗、連結或其他可追溯證據
- `blockers`：阻塞、待補資料或待確認事項
- `review`：復盤、困難、調整與下一輪計畫
- `source`：來源檔案、匯入批次或建立方式

## 導入規則

- 支援 Markdown 模板與 JSON 交換格式；CSV 不列入第一版，除非使用者另行確認欄位對應
- 導入前先檢查格式、版本、必要欄位、日期與百分比範圍
- 先顯示新增、更新、重複、無法辨識與會被忽略的項目，不直接覆蓋正式進度
- 同一 `id` 或相同來源項目視為可能重複，提供合併、保留兩筆或取消三種選擇
- 未知欄位先保留在待確認區或 metadata，不靜默丟失
- 導入失敗時保留原資料不變，回報失敗原因與可修正方式

## 導出規則

- 預設提供人可讀的 Markdown 與機器可交換的 JSON
- JSON 必須包含 `schemaVersion`、導出時間與來源資訊
- 導出前顯示範圍與敏感資料檢查結果
- 不把密碼、Token、私密路徑、完整個資、未授權逐字稿或正式 Vault 機密放入導出檔
- 導出檔可重新導入；至少驗證一輪「導出 → 清空測試資料 → 導入 → 比對」

## 進度閉環

```text
目標 → 學習項目 → 完成證據 → 進度更新 → 阻塞／下一步 → 復盤
```

只有顯示百分比而沒有項目、證據與下一步，不算完成學習進度功能。
