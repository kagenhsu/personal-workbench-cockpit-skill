# 設計靈感庫使用規則

## 定位

這 5 個資源用來研究互動、視覺、敘事、元件與品牌方向。它們是設計研究入口，不是可以整套複製進產品的依賴包

| 資源 | 主要用途 | 適合放入開發流程的階段 |
| --- | --- | --- |
| [Cuelume](https://cuelume.dev/) | 網站互動音效與回饋提示，官方目前列出 17 種 cues | 設計稿、互動驗收 |
| [Paper Shaders](https://shaders.paper.design/) | WebGL 著色器與視覺效果 | 設計稿、效能評估 |
| [Deck Gallery](https://www.deck.gallery/) | 簡報、大字報與敘事版型研究 | PM 故事結構、設計稿 |
| [21st](https://www.21st.sh/) | React 元件、模版、主題、shader 與 gradient 研究 | 設計稿、前端實作 |
| [Brand Archive](https://brandarchive.xyz/) | 色彩、字體、藝術方向與品牌應用研究 | 品牌方向、設計稿 |

## 選用方式

先問這次要解決哪一種設計問題，再選最多 1～2 個資源：

- 需要操作回饋或狀態聲音：看 Cuelume
- 需要視覺效果或動態氛圍：看 Paper Shaders
- 需要大字報或 PPT 式 HTML 敘事：看 Deck Gallery
- 專案是 React 且需要元件起點：看 21st
- 需要建立品牌色彩、字體與視覺方向：看 Brand Archive

選用結果要回寫到設計契約，至少記錄：參考哪一個資源、解決什麼問題、留下哪些設計原則、哪些內容不採用

## 與 PM、設計稿、MCP、Agent 的接法

```text
PM 釐清痛點
  ↓
設計稿選定 1～2 個靈感來源
  ↓
MCP 確認可用資料與工具權限
  ↓
Agent 依設計契約規劃與實作
  ↓
桌面、手機、流程與資料回寫驗收
```

不得因為看到元件或特效就跳過 PM 需求梳理，也不得把設計靈感當成產品功能已完成

## 安全、授權與可用性

- 不下載或複製整個網站、整套設計稿、品牌資產或第三方 Skill
- 21st 的元件使用前逐項確認授權、作者條款、依賴與技術棧，不假設所有內容條款相同
- Paper Shaders 使用前確認授權限制，並準備無 shader 的視覺退化方案
- Cuelume 音效必須可關閉，不自動播放，不把聲音當成唯一狀態提示
- 動畫與 shader 要支援減少動態、低效能裝置與手機瀏覽
- Brand Archive 只用於研究，不重製商標、Logo 或可識別品牌資產
- 本 Skill 的說明頁預設不引入上述外部依賴，只保留文字、CSS 與內嵌示意圖

## 驗收問題

1. 使用者是否知道這個靈感解決哪個痛點
2. 介面在沒有音效、shader 或外部載入時是否仍可用
3. 手機與桌面是否都能讀懂主要流程
4. 是否保留成功、失敗、等待、取消與錯誤文字
5. 是否有授權、依賴、效能與品牌使用紀錄
