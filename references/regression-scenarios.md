# 前向回歸情境

建立或重大修改 Skill 後，至少用下列情境檢查實際首輪決策。重點是行為，不要求逐字相同。

## 應觸發

1. **自然語言新建**：「我想做一個個人控制台，但不知道怎麼開始。」
   - 自動進入探索模式；先用痛點選擇題，不要求使用者輸入 Skill 名稱或格式，也不直接開始寫程式。
2. **自然語言摩擦**：「首頁太亂，我看不到今天要做什麼。」
   - 先提供 2～4 個痛點／結果選項，再問一題使用情境；未選定方案前不改 UI。
3. **自然語言新增功能**：「我想加設備提醒。」
   - 先確認是保養遺漏、異常追蹤、到期管理或其他痛點，再提出 2～3 個方案。
4. **明確錯誤**：「這個按鈕按了沒反應。」
   - 直接進入診斷，不重跑完整痛點訪談；完成後仍需實際驗收。
5. **既有專案延續**：「把現在 localhost、SQLite 的人生控制台做成手機版並繼續改。」
   - 先找真實入口與版本狀態；不把 localhost 直接公開；詢問跨裝置資料與使用網路；展示並核准手機版型後才實作。
6. **多人管理工作台**：「做一個可寫入、可查詢、多人登入的銷售管理工作台。」
   - 啟動新建流程；優先處理身分、角色、資料隔離、伺服器資料庫、稽核、備份與部署，不以 localStorage 當真相。
7. **直接要求開發但資料完整**：使用者已提供功能、平台、版型、權限、資料、部署與驗收，並說開始做。
   - 不重跑整份問卷；先回述短開發契約，只有真正缺口才問；取得明確核准後實作。
8. **教學轉換**：「把已完成的控制台整理成新手課程。」
   - 先核實功能與驗收證據；只教已完成內容，區分正式資料、假資料、規劃與未完成。
9. **UI 搭配流程**：「首頁太亂，我看不到今天要做什麼。」
   - 先確認痛點與方案；方案選定後才使用 UI／UX Skill 檢查資訊層級與響應式，不直接重做首頁。
10. **純後端修改**：「只調整工作項目的 API 驗證。」
   - 使用工作台資料與安全規則，但不啟動 UI／UX Skill。
11. **生成前四項藍圖**：「我要做一個給創作者用的工作台，把選題變成腳本，設定發布時間，發布後看數據再復盤。」
   - 先確認使用者、反覆處理對象、完整流程與最後要看的結果；確認前不生成卡片式 UI。
12. **長期訪問要求**：「我要做成可以一直打開的網址或行動 App。」
   - 先確認保存位置、跨裝置、備份／恢復、權限與部署方式；不把可開啟入口當成完整產品證據。
13. **駕駛艙四功能**：「我想每天知道今天要做什麼、整合專案狀況、幫我判斷下一步，再把決定變成任務追蹤。」
   - 先確認推、看、決、令各自的資料來源、使用者操作與結果紀錄；至少提出一條可驗收的閉環，不直接生成靜態卡片。
14. **複雜需求拷問**：「我想做一個跨裝置的學習工作台，但還不知道要不要登入、要不要同步。」
   - 搭配 `grill-me` 一次問一題，先釐清使用者、學習對象、保存方式、同步需求與驗收，不一次拋出整份問卷。
15. **學習進度交換**：「我要把課程進度保存下來，換電腦後還能導入，最後可以導出備份。」
   - 使用 `LearningProgress`；導入前預覽格式、版本與重複項目，完成 Markdown／JSON 導出與測試導入往返，不直接覆蓋正式資料。
16. **Cloud Studio 部署**：「把這個工作台用 Cloud Studio 部署成可以一直開啟的網站。」
   - 先確認實際 Cloud Studio 供應商、網站類型、資料持久化、權限、費用與可見性；本機驗收與使用者確認前不公開部署。
17. **PM、設計稿、MCP 與 Agent 流程**：「不論網站或行動 App，都要先把需求、設計、MCP、Agent 分工與開發落地接起來。」
   - 讀取 PM 開發流程規則；先產出短開發契約與設計稿驗收範圍，再盤點 MCP 的資料／工具權限與 Agent 交接；未核准前不直接開發或連接正式服務。
18. **高保真設計到開發**：「用 PM Skill 和 grill-me 梳理後，做一套可編輯的高保真系統設計，再透過 MCP 交給 Agent 用 D2C 落地。」
   - PM 與 `grill-me` 一起確認目標用戶、核心場景、頁面結構、8 項 UI 規範與驗收；設計稿必須是可編輯源文件；MCP 只交接最小必要資訊；Agent 依設計變量、元件狀態與資料欄位產出程式，不把單張圖片或範例代碼當成完成產品。

## 不應觸發

1. 「幫我畫一張本月銷售折線圖。」——單一圖表。
2. 「解釋 Dashboard 這個英文是什麼。」——只問名詞。
3. 「整理這份一次性的週報。」——一次性報告，除非使用者要建立可持續寫入與查詢的工作台。
4. 「幫我做一張統計圖。」——單一圖表，不因出現 Dashboard 或資料而啟動工作台探索。

## 共同失敗條件

- 一次問多個未決問題或重問已知答案。
- 使用者只說「這裡不順」時，要求使用者記住 Skill 名稱、提示詞或固定格式。
- 未確認痛點與方案就直接提出技術實作或修改檔案。
- 核准前改任何程式、設定、依賴、資料、部署或狀態檔。
- 讓新手自行猜技術，沒有依情境提出推薦。
- 有漂亮 UI 就宣稱具備登入、資料庫、同步、備份或 PWA。
- 有推送卡片、統計卡片或 AI 建議就宣稱具備推、看、決、令；四項都必須對應實際資料、操作與結果紀錄。
- 把私人資料放入公開展示、Skill 目錄、教學素材或未知外部服務。
