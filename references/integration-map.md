# 三個來源的整合範圍

## 來源

| 來源 | 角色 | 整合方式 |
|---|---|---|
| `console-builder-skill` | 通用控制台建造流程 | 保留需求模式、開發契約、架構、驗收與持續演化參考文件 |
| `ai-personal-workbench-private` | 實際個人工作台產品 | 只抽取已驗證的資料模型、資料邊界、工作領域與驗收經驗；不複製正式資料與私密設定 |
| `ui-ux-pro-max` | UI 設計系統與 UX 檢查 | 只在畫面／互動／響應式需求中搭配使用；不複製完整內容，不取代痛點探索與資料守門 |

## 保留

- 先讀現況再延續，不從頭假設。
- 工作項目、進度日誌、提醒、Dashboard 與草稿的邊界。
- Markdown／Obsidian 作為正式資料來源時的保護規則。
- 五個正式職務領域與「待分類」狀態。
- 測試、指定路由、實際 UI 與 Git 狀態的分層驗證。
- UI 任務的設計系統、資訊層級、互動與無障礙檢查；依實際 Web 技術棧調整，不套用不適用的 React Native 指令。

## 不納入

- 實際工作台的 Node.js、HTML、CSS、API 或資料檔。
- Vault 實體路徑、帳號、密碼、Token、API Key、Cloudflare 設定與正式工作紀錄。
- `kagen-assistant` 的個人履歷、人設與可識別個人資訊。
- 任何未在來源專案驗證完成的規劃功能。
- 自動推送 GitHub、修改正式 Vault、啟動背景排程或外部通知。
- `ui-ux-pro-max` 的完整 Skill 內容、第三方資料庫與搜尋結果；只抽象可泛用的設計流程與檢查點。

## 版本策略

這個 Skill 是獨立產品，不直接修改三個來源 repo。來源專案若有新規則，先比較差異、確認可泛化，再以小版本更新；不要把一次性偏好直接寫成通用規則。
