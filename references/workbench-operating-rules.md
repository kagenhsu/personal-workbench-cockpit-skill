# 個人工作台運作規則

本文件把 AI 個人工作台的可泛用規則抽出，避免把單一專案的程式碼、正式資料或私密設定直接放進 Skill。

## 資料真相

- 工作項目、進度日誌、提醒與每日摘要優先保存為使用者指定 Vault 內的 Markdown。
- 網頁是操作介面，不是另一份獨立業務資料庫；若確實需要本機資料庫，先定義它的範圍與非正式資料性質。
- 每個工作項目可累積多筆進度；進度紀錄採新增，不覆寫舊紀錄。
- AI 產生的內容先放在草稿區或回應中，確認後才進入正式資料。
- 舊資料缺少新欄位時保留原資料，顯示「待分類」或「待補」，不自行猜測。

## 預設工作欄位

工作項目可以包含：

- 標題與目前狀態
- 主職務與相關職務
- 職務階段
- 目前內容與下一步
- 預估分鐘
- 計畫日期與時段
- 專案、追蹤時間與提醒狀態
- 版本與去重識別碼

欄位名稱要以現有專案實際模型為準；本清單是設計檢查點，不授權直接改 schema。

## 五個正式職務領域

1. 監控設備管理：巡檢、異常判斷、處理與廠商追蹤。
2. 辦公室電腦相關設備：需求、檢查、處理／採購與交付。
3. 公司系統開發與管理：需求、開發／設定、測試、上線與維護。
4. 工地空拍影像紀錄：排程、拍攝、整理與交付／歸檔。
5. 網路數位行銷：規劃、製作、發布與成效觀察。

值日工作、臨時雜務與正式職務工作要能分開查詢；不要因為都叫「工作」就混成一個統計。

## AI 與正式寫入

推薦流程：

```text
輸入 → 讀取可用資料 → 產生草稿 → 顯示來源與不確定性 → 使用者確認 → 寫入 → 回讀驗證
```

AI 不得自行新增日期、完成狀態、負責人、金額、專案關聯或敏感結論。資料不足時寫「待確認」。

## 工作台驗收

- 首頁統計必須來自真實 API 或正式資料，不得使用展示用固定數字。
- 新增工作、更新狀態、追加進度與刷新頁面後的持久化都要分開驗證。
- 指定路由要實際開啟確認；登入頁成功不代表工作項目頁成功。
- 使用測試 Vault 驗證寫入，避免把本機正式 Vault 當測試資料夾。
- 視覺測試未執行時，回報中保留「視覺驗收待確認」。
